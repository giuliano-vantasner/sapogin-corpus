# sapogin-corpus

Claim corpus and campaign workspace for Vladimir G. Sapogin's "Canonical
Physics" (https://sapogin.com/), built for LENR/EVO research (Dan, Tiziano).
Governance inherited from `vantasnerdan/substrate-framework` — see
[AGENTS.md](AGENTS.md) for the binding contract.

## Layout

- `papers/` — every document referenced by the site (PDFs + `MANIFEST.yaml` +
  `MD5SUMS` + `text/` extractions + `DOWNLOAD-REPORT.md`).
- `site/` — rendered text of the site pages (Russian, structure preserved).
- `claims/source/` — `SC-*` source claims, verbatim-faithful, provenance-pinned
  (schema: [claims/SCHEMA.md](claims/SCHEMA.md)).
- `claims/coverage.yaml` — document → claim-file coverage map.
- `claims/claims.jsonl` — flattened claim stream for GitNexus ingestion
  (generated by `tools/build_jsonl.py`).
- `clusters/` — GitNexus clustering outputs → physics-path candidates.
- `governance/` — `policy.yaml` (this repo's policy), `claims.yaml` (our
  adjudicated `GC-*` claims), `debt.yaml` (named gaps campaigns resolve).
- `campaigns/` — substrate-anatomy campaigns per cluster/path
  (practical layer first, theory after).
- `memory-templates/`, `.agents/skills/` — ported from substrate-framework.
- `tools/` — `validate_corpus.py`, `build_jsonl.py`, `gitnexus_ingest.py`,
  `extract_pdf_text.py`, site inventory + JS chunks.

## Priority question (Tiziano/Dan)

Why do charge clusters (EVOs) help with catalysis and possibly EVO
generation — materials, geometries, procedures, measurements, isotope
transmutation — as the KEY input for the electrical path? Practical-layer
claims are `priority: core`; campaigns run practical-first, theory after,
adjudicated through our CQED framework (battle testing).

## Loop

```
inventory → download → extract text → extract claims → validate → review
  → gitnexus analyze + cluster → campaigns (CQED lens) → adjudicate → promote
```
